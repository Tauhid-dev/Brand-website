# Documentation Skill

- **Purpose:** Create authoritative, navigable, audience-specific operational knowledge.
- **When to use:** Any behavior, contract, decision, operation, workflow, or state change.
- **When NOT to use:** To duplicate generated facts that should be linked.
- **Inputs:** Verified behavior, audience, ownership, examples, failure/recovery paths.
- **Outputs:** Guides, reference, ADRs, runbooks, cross-links, updated memory.
- **Dependencies:** Source artifacts and validation commands.
- **Example:** Add a migration guide linking schema diffs, compatibility window, verification, and rollback.
