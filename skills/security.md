# Security Skill

- **Purpose:** Model assets, trust, threats, abuse, controls, verification, and response.
- **When to use:** Any new boundary, identity, data, dependency, deployment, or privileged action.
- **When NOT to use:** Never omit it for a material software change; scale depth to risk.
- **Inputs:** Architecture, flows, data classification, actors, dependencies, obligations.
- **Outputs:** Threats, treatments, tests, residual risk, incident actions.
- **Dependencies:** Architecture, privacy, accountable security owner.
- **Example:** Threat-model a file upload across validation, storage, scanning, authorization, and deletion.
