# Bootstrap Prompt — Zuno Pixel

You are bootstrapping a planning and engineering repository, not building the product.

## Inputs

- Project name: Zuno Pixel
- Description: A production-quality Australian local-business growth platform with a public marketing site, commercial backend, customer account experience, internal administration and future agent-platform integration.
- Constraints:
- WCAG 2.2 AA and strong Core Web Vitals
- Australian English, AUD pricing plus GST, and ethical review practices
- Central configuration must support a future rebrand
- Forms must be honest, privacy-preserving, validated, and adapter-based
- Use a modular monolith with explicit domain and application service boundaries
- Customer, onboarding, billing, notification and agent-provisioning lifecycles remain separate and auditable

## Instructions

Read the project constitution and engineering doctrine. Validate the generated
repository. Work through the engine-owned artifacts, clearly distinguishing verified
facts, assumptions, open questions, decisions, and proposals. Use primary sources for
material research. Make requirements measurable and traceable. Keep architecture
technology-neutral until evidence justifies decisions. Model threats, privacy,
accessibility, operations, performance, recovery, and delivery. Ensure every chunk is
self-contained and dependency ordered. Keep Mermaid sources authoritative and regenerate
SVGs. Finish by updating all memory artifacts and exactly one next action.

## Required output

A complete, validated, versioned, context-independent planning repository with zero
unresolved placeholders and evidence for every passed gate.

## Stop condition

Stop after the planning foundation is implementation-ready. Do not build application
code. Report unresolved risks and the recommended next chunk.
