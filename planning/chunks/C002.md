## Implementation Plan

1. Verify dependencies and starting state.
2. Identify assumptions, risks, decisions, and required research.
3. Make the smallest coherent changes that satisfy the purpose.
4. Run proportionate tests and every affected validator.
5. Review cross-references, security, rollback, and documentation.
6. Record evidence and update all memory views atomically.

## Tests

- Happy, boundary, invalid, failure, and recovery paths are addressed.
- Generated and machine-readable artifacts validate.
- Repeat generation is deterministic where applicable.
- Relevant security and non-functional risks have evidence.

## Acceptance Criteria

- Declared outputs exist and satisfy their contracts.
- All dependencies and assumptions are explicit.
- No unresolved placeholders, broken references, or unowned risks remain.
- Reviewable completion evidence is recorded.

## Documentation Updates

Update architecture, ADRs, requirements traceability, risks, status, progress,
decision summary, current state, session handoff, and next action as affected.

## Git Requirements

Use a focused diff and logical commit. Do not mix unrelated user changes. Record
the revision in completion evidence and push only when authorised.

## Rollback

Identify reversible steps before execution. Preserve prior contracts or provide an
explicit migration. Verify rollback for any externally visible or stateful change.

## Risks

Review the risk register and add newly discovered threats, delivery risks, and debt
with an owner and treatment.

## Completion Evidence

Record commands, results, artifact hashes or links, reviewer, deviations, residual
risks, documentation updates, and the exact next action.
