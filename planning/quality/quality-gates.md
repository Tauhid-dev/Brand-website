# Quality Gates — Zuno Pixel

No component is complete until documentation, validation, templates or contracts,
appropriate examples, cross-references, and versioning are present.

| Gate | Required evidence | Owner | Failure action |
| --- | --- | --- | --- |
| Intent and requirements | Approved outcomes, requirements, acceptance traceability | Product owner | Return to planning |
| Architecture | Boundaries, dependency rules, ADRs, current diagrams | Architect | Block implementation |
| Security and privacy | Threats, controls, scans, treatment and residual-risk approval | Security owner | Remediate or time-bound waiver |
| Code and contracts | Review, static checks, compatibility and migration evidence | Engineering lead | Correct before merge |
| Testing | Risk-based automated and manual results linked to revision | QA owner | Fix, quarantine with owner, or reject |
| Non-functional | Performance, resilience, recovery, accessibility, and operability evidence | Service owner | Rework design or scope |
| Documentation and memory | Current docs, evidence, status, handoff, and exactly one next action | Chunk owner | Chunk remains incomplete |
| Delivery | Provenance, promotion, monitoring, rollback, and release approval | Delivery owner | Do not release |

## Waivers

A waiver identifies the failed gate, authority, rationale, exposure, compensating
controls, expiry, remediation owner, and tracking reference. Expired waivers fail.
