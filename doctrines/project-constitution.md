# Project Genesis Constitution

## Authority

This constitution governs the framework and every generated foundation. Exceptions
require a named authority, rationale, risk, compensating control, and expiry.

## Engineering

Generate the smallest coherent foundation that satisfies traceable outcomes. Keep
modules cohesive, contracts explicit, behavior deterministic, changes reversible, and
evidence reproducible. Complexity and dependencies require a named benefit.

## Architecture

Architecture defines boundaries, ownership, dependency direction, quality attributes,
and material trade-offs. Stable policy owns its abstractions. Technology follows
requirements and research. Material decisions are immutable ADRs that may be superseded.

## Documentation

Documentation is a versioned interface and part of the change. Generated repositories
must be navigable, cross-referenced, machine-validatable, and resumable without chat.
Mermaid is the authoritative diagram source; SVG is a verified derivative.

## Security and privacy

Apply least privilege, deny by default, data minimisation, explicit trust boundaries,
secure defaults, protected delivery provenance, safe failure, recovery, and a managed
vulnerability lifecycle. Never place secrets in source, prompts, logs, or memory.

## Testing

Tests provide risk-based evidence for contracts, invariants, negative paths, failure,
recovery, security, privacy, accessibility, performance, and operations. Flaky or
untraceable results do not pass a gate.

## Artificial intelligence

AI output is untrusted contribution. Give agents bounded inputs, owned outputs,
constraints, stop conditions, and validation commands. Humans retain accountability.
Verify sources, code, licenses, security, tests, and repository memory.

## Review

Review behavior, risk, architecture, compatibility, migration, rollback, operability,
maintainability, accessibility, privacy, and evidence. Completion requires independent
challenge proportionate to risk.

## Change management

Use focused, logical, versioned changes. SemVer communicates public compatibility.
Breaking changes require a migration path. Status, decisions, risks, evidence, and
resume state change atomically with the work they describe.
